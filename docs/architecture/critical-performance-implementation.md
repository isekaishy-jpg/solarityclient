# Critical frame work, September 12, 2026

This implements the structural work from the [critical cost audit](critical-performance-audit-2026-09-12.md),
against baseline `0124053e`. It does not establish a new live FPS result or turn
the 1,200 FPS stretch target into a guaranteed frame deadline.

## Recurring work

- `ActiveWorld` retains sorted unit membership when objects enter, change kind,
  or leave. Residency, movement, and passenger consumers borrow the same list.
- NPC and remote-player residency retain their exact mutable appearance inputs,
  including ECS lifetime identity. Unchanged owners update motion and animation
  without repeating model/equipment/atlas planning. Animation binding visits the
  population just published rather than binding both populations twice.
- UI geometry owns reverse parent/anchor links. A mutation traverses its dependent
  island; retargeting and failed cyclic transactions update those links atomically.
  The retained publisher no longer clones the complete geometry arena.
- UI content resolves named presentation owners, pointer facts, and scroll state.
  General layout publication uses the same geometry index and replaces affected
  presentation membership; packet reindexing visits renderable members. Existing
  retained texture/glyph runs remain available for stable topology.
- WMO registration/liquid queries use a conservative root AABB hierarchy and
  restore original root order before native narrow-phase tests. The hierarchy
  rebuilds only when the scene geometry revision changes. Camera results are
  reused within one service frame only while all captured providers still match.
- M2 loading precomputes parent order, nearest finger ancestry, and the entirely
  untracked/non-billboard bind-pose fact. Sequence override clocks propagate in
  parent order. Per-instance clocks, events, random consumption, billboards,
  equipment, and animated values retain their existing paths.

## Admission and lifetime ownership

Remote-player and NPC archive/model/texture/atlas work runs in finite CPU jobs on
private archive/cache owners. Each population has one outstanding request, with
no per-object FIFO backlog. Completed work must still match the current object
lifetime, appearance key, and component texture level. Replaced or obsolete
large CPU resources retire through the executor; saturation retains ownership.
An active unit generation keeps its reconciliation state and independent motion
until its complete replacement publishes; removal still retires that owner.
Explicit synchronous loading APIs remain available to offline callers.

Prepared units pin shared immutable M2 mesh/program sources. GPU publication
reuses those plans. Pipeline admission skips resident identities and admits one
cold program at a time; a mesh program includes its primary-shadow partner.
`M2SpirvCompiler` selects build-generated bytecode: the audit's original claim of
runtime shaderc compilation was incorrect.

Neighboring ADTs now wait outside CPU collision and visible GPU membership while
terrain geometry, material images, layer textures, liquid resources, and model
sources are staged. Static M2 preparation separates pipeline admission from
source upload; WMO sources are prepared individually. Completed resources transfer
into ordinary scene publication. Only then is the tile admitted to collision and
draw membership in the same service transaction. Staging does not create model
placements or consume their animation randomness. Cancellation retires unpublished
liquid/terrain resources through the existing renderer ownership rules.

Ground detail uses one finite scatter/mesh job and admits one completed chunk per
service. Exact ADT and density identities reject obsolete meshes and obsolete
asset errors. Native placement, visibility, density, and texture behavior remain
unchanged.

Network dispatch snapshots the admitted channel batch. Producer refill waits for
the next service; packets and object-update transactions remain ordered and
indivisible. [Pinned stock evidence](../research/network-frame-batch-12340.md)
documents the native queue lock that establishes this boundary.

## Cost boundaries and validation

These changes remove repeated global discovery and synchronous population asset
bursts. They do not impose an arbitrary timer on necessary atomic work. A driver
program pair, one large WMO source, one liquid resource transaction, a large wire
packet, or final placement activation can still be expensive. Initial world
loading retains its loading-screen path. New UI object arenas, missing glyph
coverage, and native role reparenting retain complete reconstruction where the
incremental contract does not apply; packet membership changes can rebuild the
visible render mesh. Those boundaries remain visible to the existing opt-in frame
scopes and should be evaluated with a populated live capture before further work.

Regression coverage includes reverse-link retargeting/cycle rollback, ordered
spatial candidates, producer refill during packet callbacks, stale GUID reuse
during population admission, saturation-safe retirement, deferred terrain
publication, and mixed UI packet insertion/removal/reordering. Existing stock
animation, equipment, collision, UI, and GPU rendering tests cover behavior
preservation. Formatting, workspace Clippy with all targets and features and
warnings denied, and the all-feature workspace test suite passed before rebasing
onto Testing Build 123. The combined result is checked again before publication.

Large modified areas are split into folder-backed UI geometry/publication,
presentation resolution, population preparation, M2 source admission, and terrain
admission modules. No new compatibility or asset substitution policy is added.
